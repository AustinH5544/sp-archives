# SP-ARCHIVES — architecture decisions and roadmap

Running record of what was decided and why. Updated 2026-08-28.

## Hosting

Cloudflare **Workers Static Assets**, not Pages.

Pages is not deprecated and has no announced end-of-life. Cloudflare's docs
say "Start new projects with Workers" — a steer, not a forced migration. We
moved because Workers has the broader feature set, not because Pages is
going away. `sp-archives.pages.dev` still exists as a fallback.

`wrangler.jsonc` deliberately has **no `main` key**. With no Worker script,
asset requests are served directly and are free/unbilled. Adding a script
(for a contact-form API, or to proxy R2) turns every matching request into a
billed Worker invocation. Weigh that before adding one.

Live on `sp-archives.com` and `www.sp-archives.com` as custom domains, so
the Worker is the origin and Cloudflare issues the certificates itself.

The account is **Skyelar's** (`68fd0549e41d1746b1ddb0ed5ce0f4b6`), not
Austin's. Austin currently has Super Administrator + Billing, which is more
than needed — should be reduced to Administrator. Only Skyelar can do that.

## CI/CD

GitHub connected via **Workers Builds** (dashboard-only; there is no API for
the connection). Production branch `master`, build `npm run build`, deploy
`npx wrangler deploy`.

Non-production branch builds are enabled. These run `npx wrangler versions
upload`, **not** `wrangler deploy` — so pushing a feature branch uploads a
version but never promotes it to production. Only `master` goes live.

The Worker name in the dashboard must match `name` in `wrangler.jsonc` or
the build fails. Both are `sp-archives`.

## Caching (`public/_headers`)

Cloudflare's default for every static asset is
`Cache-Control: public, max-age=0, must-revalidate`. Correct for HTML, but
it meant a returning visitor re-validated all 36 plates of a gallery on
every load — 36 round trips each returning 304 and zero bytes.

- `/_next/static/*` → one year, `immutable`. Next content-hashes these, so a
  changed file is a changed URL. Also covers the self-hosted fonts.
- `/work/*` → one day, **not** `immutable`. The photos are `01.jpg`,
  `cover.jpg` — no content hash. `immutable` would mean a replaced frame
  never reaches a returning visitor. Rename the file if a swap must be seen
  immediately.
- `workers.dev` preview URLs → `X-Robots-Tag: noindex`.

`.gitattributes` pins this file to LF so the Cloudflare parser sees clean
lines regardless of platform.

Note: `_headers` does **not** apply to responses generated by Worker code,
and does not apply to a different hostname. If photos move to an R2 custom
domain, the `/work/*` rule becomes dead and must be deleted.

## Image quality — the plan

**Storage location is not the quality lever.** A JPEG is byte-identical in
R2 or in the repo. The current ceiling is `images.unoptimized: true`, which
serves one file to every device: no srcset, no format negotiation. Plates
are 1800px, cover 2400px. A full-bleed hero on a 5K display wants ~5120
device px, so it upscales ~2x and looks soft on large monitors.

The fix has three parts:

1. **Bigger masters.** Long edge 4000–5000px. At q90 that is 4–8 MB each;
   ~250 photos is 1–2 GB. Too big for a git repo or the assets bundle —
   *this* is what makes R2 necessary. R2 does not improve quality, it
   removes the ceiling that forces images to stay small. Fits the 10 GB
   free tier.

2. **Cloudflare Images transformations** for delivery. Free tier is 5,000
   unique transformations/month; 250 photos x 5 breakpoint widths = 1,250.
   `format=auto` counts as ONE transformation whether served as AVIF or
   WebP, so format negotiation is free. AVIF is ~half the bytes of JPEG at
   equal quality, which buys roughly double the pixel dimensions per byte.

   Constraint: use **fixed breakpoint widths**. Viewport-derived widths
   (`w=1247`) would create a unique transformation per visitor and burn
   through 5,000 quickly.

3. **`images.loaderFile`** in Next 16 — verified supported under
   `output: export`. Replaces `unoptimized: true` and gives real srcset:

   ```js
   export default function loader({ src, width, quality }) {
     return `/cdn-cgi/image/width=${width},format=auto,quality=${quality || 85}${src}`
   }
   ```

### Export specs for Skyelar

Give him these **before** he processes the remaining collections —
re-exporting later is painful and the current 1800px files are already
below target.

- Long edge **4000–5000px** (was 1800)
- **sRGB, profile embedded.** The quietest quality killer. AdobeRGB or
  ProPhoto exported without a profile renders dull and desaturated in
  browsers, and reads as bad grading rather than a technical fault.
- Quality **90+** — we downsample at delivery, so don't pre-compress
- **No output sharpening** — transformations resize afterward, and
  sharpened-then-resized produces crunchy edges

Transfer as originals, not through Pixieset (it re-encodes).

## Delivery to clients

Skyelar already pays $10/mo for **Pixieset**, which solves client galleries
and downloads. Not rebuilding that. The site is a portfolio, not a delivery
system.

## Rejected

- **ImageKit** in front of R2 — the original plan. Dropped for native
  Cloudflare transformations: one vendor, one bill, one cache, and the free
  tier covers this site's scale.
- `not_found_handling: "single-page-application"` — every route is
  prerendered, so the 404 page is correct.
- `generateStaticParams()` returning `[]` — fails the build under
  `output: export`. The journal switch moves the route folder instead.
